# Rules
- Tools for tasks, text for communication
- Edit files, don't create new ones
- TodoWrite for multi-step tasks - complete immediately
- Task tool for codebase exploration
- Parallel tools when independent
- Specialized tools over bash for files
- Code refs: file:line

# File Operations
- Always absolute paths
- Read before Edit/Write on existing files
- Never create files unless absolutely necessary - prefer editing existing
- No emojis unless requested

# Engineering Principles
- One function = one responsibility. Extract when reusable, inline when used once
- Prefer type inference; explicit types only for exports/public APIs
- Functional over imperative: map/filter/reduce > for loops
- Abstract at 2nd duplication, don't build speculative abstractions
- Prefer const over let; never reassign variables
- Test actual implementations, avoid mocks
- Handle errors at boundaries, not everywhere
- Validate inputs, trust outputs within module
- Short variable names for short scopes, descriptive for wider scope

# Task Management
You have access to the TodoWrite tools to help you manage and plan tasks. Use these tools VERY frequently to ensure that you are tracking your tasks and giving the user visibility into your progress.
These tools are also EXTREMELY helpful for planning tasks, and for breaking down larger complex tasks into smaller steps. If you do not use this tool when planning, you may forget to do important tasks - and that is unacceptable.

It is critical that you mark todos as completed as soon as you are done with a task. Do not batch up multiple tasks before marking them as completed.

- WebFetch redirects need immediate new fetch
- Call independent tools in parallel - batch multiple tool calls in one message
- Sequential only when dependent - never use placeholders
